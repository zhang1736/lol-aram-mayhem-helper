# 识别与推荐响应速度报告

测量日期：2026-10-24  
环境：Windows、Python 3.12.10、`rapidocr_onnxruntime 1.4.4`、ONNX
`intra_op_num_threads=2` / `inter_op_num_threads=1`

## 改造前基线

使用 `research/captures/augment_cards_fixture.png` 的真实三卡样本和真实
RapidOCR，连续 7 次：

| 项目 | P50 | P95 | 最大 |
| --- | ---: | ---: | ---: |
| OCR 首次初始化 | 936.9 ms | - | 936.9 ms |
| 首次三卡识别 | 45.2 ms | 67.6 ms | 67.6 ms |
| 静态三卡复用 | 0.3 ms | 0.3 ms | 0.3 ms |
| 换牌后变化槽识别本体 | 15.6 ms | 17.0 ms | 17.0 ms |

旧逻辑在变化槽识别前有固定 750 ms 最小间隔，Qt 浮层还有最长 200 ms 轮询等待。

## 改造后测量

同一真实样本和真实 RapidOCR，连续 9 次：

| 项目 | P50 | P95 | 最大 |
| --- | ---: | ---: | ---: |
| OCR 首次初始化（已移到后台） | 556.2 ms | - | 556.2 ms |
| 预热后首次三卡识别 | 44.9 ms | 65.1 ms | 65.1 ms |
| 静态三卡复用 | 0.3 ms | 0.4 ms | 0.4 ms |
| 换牌后变化槽识别本体 | 15.2 ms | 18.0 ms | 18.0 ms |
| Qt 跨线程更新三卡浮层 | 2.33 ms | 8.18 ms | 18.02 ms |

当前 Windows 桌面下 `mss` 抓取 1410x58 名称带：P50 6.94 ms、P95 8.08 ms、
最大 37.68 ms。单独测量稳定牌面与 watchdog 时，一次性 ONNX 初始化收尾后
OCR 调用数均为 0；稳定牌面约 0.31% 单核等效，窗口外 watchdog 约 0.30%
单核等效。以上为开发机测量，CPU 总占用仍会受游戏、显卡驱动和系统环境影响。

## 估算端到端路径

| 场景 | 主要路径 | 开发机估算 |
| --- | --- | --- |
| stage 已武装后的首次显示 | 三卡 OCR + 本地查表 + 推荐 + Qt 更新 | 约 50-75 ms |
| 单槽换牌 | 最多 250 ms 等下一采样 + 250 ms 新帧确认 + 单槽 OCR + Qt 更新 | 约 0.3-0.6 s |
| 第一次选取后的下一阶段 | Live Client 最多 500 ms 发现等级 + 全量 OCR + Qt 更新 | 约 0.55-0.65 s，另加游戏自身阶段切换时间 |
| OCR 尚未预热完成时出现海克斯 | 识别线程等待同一个初始化锁，完成后立即复用 | 模型加载完成后继续，不重复创建实例 |

这些是受控样本和本机测量，不等同于真实对局 P95。当前机器没有运行中的
`LeagueClientUx.exe` / `League of Legends.exe`，因此无法在本次交付中宣称真实
对局 P95 已达到目标；`PERF` 日志已可在下一局直接采集真实验证数据。
